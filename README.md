# Gaze Lab

A visual tool for learning and doing eye-tracking analysis without programming.
You build a pipeline from steps (load, clean, detect fixations, areas of
interest, summarise) and at every step you can see the data that went in, the
data that came out and what the step did to it. The same pipeline works on the
simulated teaching examples and on your own recordings, and ends in CSV tables
for JASP, jamovi or R.

The eye-movement mathematics is not Gaze Lab's own. Cleaning and event
detection are done by [pymovements](https://pymovements.readthedocs.io), an
open-source Python package for eye-tracking data. Each of those steps shows
the pymovements calls it makes as a short script with your settings filled in,
so students can take the same code into their own analysis.

It replaces the earlier R/Quarto course material and the first version of the
app; both are kept under [`legacy/`](legacy/).

## Start it

With Docker (recommended, also for a server):

```sh
docker compose up -d --build
```

Open <http://localhost:8000>. Stop it with `docker compose down`; uploaded
recordings survive in a Docker volume. For a server with HTTPS and a password,
settings, sizing and updates, see [docs/deployment.md](docs/deployment.md).

Without Docker (for development; tested with Python 3.14 and Node 26, and the pinned packages need a recent Python):

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
npm ci --prefix frontend && npm run build --prefix frontend
.venv/bin/python -m uvicorn server.app:app --port 8000
```

While working on the web app, run `npm run dev --prefix frontend` next to the
server and open the address Vite prints; it forwards `/api` to port 8000.

## What you get

**One screen, three columns.** Left: the pipeline, read from top to bottom,
and the steps you can add. Middle: the data at the selected step, switchable
between *Input* and *Output*, as figures or as tables. Right: what the step
does, its settings, what it reported, a question to think about, and its
Python code. Steps calculated by pymovements also offer *Do this step in your
own Python script*: a script that reproduces the step outside the app.

**Every change runs immediately.** Change a threshold and the fixation count
on the step updates; only that step and the ones after it are recomputed.

**Steps** (each is one Python class, see [docs/extending.md](docs/extending.md);
those marked ● are calculated by pymovements):

| Stage | Steps |
| --- | --- |
| Load | Load recording |
| Prepare | Cut trials from markers · Add trial information · Trim trials in time |
| Clean | Correct drift · Remove off-screen gaze ● · Detect and remove blinks ● · Fill short gaps · Reduce noise ● · Baseline-correct pupil |
| Detect events | Fixations by speed (I-VT) ● · Fixations by spread (I-DT) ● · Saccades (Engbert & Kliegl) ● · Use the tracker's own fixations |
| Areas of interest | Draw areas · Areas from file columns · Measure attention per area · Count transitions · Find viewing patterns |
| Summarise | Summarise each trial · Build a table for statistics (long or wide) |

**Your own data.** Upload one file per participant. Recognised automatically:

- Tobii Pro Lab data exports (TSV) of Tobii Pro Glasses 2/3 and screen trackers
- Tobii Pro Glasses 2 raw recordings (`livedata.json.gz` from the SD card)
- EyeLink ASC files (parsed by pymovements)
- WebGazer experiments: the `.xlsx` workbook the experiment page saves, with the images that were shown
- any CSV/TSV of gaze samples, with a column-mapping dialog

Details, required columns and caveats: [docs/data-formats.md](docs/data-formats.md).

**Results you can take away.** Any table at any step downloads as CSV (also
in a variant with semicolons and decimal commas for Excel), any figure as PNG. *Export results* produces a zip with every step's tables, the
pipeline, the data and a script that reproduces everything without the app
(`python run.py`).

**Six worked examples** on four simulated datasets, each with a short list
of things to try: from samples to fixations, AOI measures and a paired
comparison, pupil cleaning, a Tobii Glasses 2 shelf study (Pro Lab export),
a raw Glasses 2 recording, and free viewing of four faces (first look against
lasting look). See [docs/teaching.md](docs/teaching.md).

**A ten-hour teaching block in Czech** with a lesson plan, printable
worksheets and an answer key is in [`vyuka/`](vyuka/00%20Rozcestník.md).

## The example data are simulated

`examples/datasets/` is generated by `examples/generate.py` from a simple
model of eye movements (fixations, saccades, blinks, lost tracking, a pupil
that reacts to difficulty). Because the true fixations are known and stored in
each dataset's `truth/` folder, students can check what a pipeline recovers.
The files imitate real export formats, but they are not recordings of people
and support no scientific conclusion.

## Layout of the repository

```
gazelab/          the analysis engine; plain Python, no web code
  core.py           the contract: Bundle, settings, Node, registries
  bridge.py         hands samples to pymovements and reads the result back
  pipeline.py       runs a graph of steps, caches results
  nodes/            the steps, one module per stage
  readers/          file formats, one module per format
  views.py          figures (Plotly descriptions built in Python)
  cli.py            python -m gazelab run pipeline.json
server/app.py     the HTTP API around the engine
frontend/         the web app (Vue 3, Vite)
examples/         simulated datasets, example pipelines, their generator
vyuka/            Czech lesson plan, worksheets and their data (an Obsidian folder)
plugins/          drop-in steps loaded at start-up
tests/            pytest suite
docs/             deployment, data formats, extending, teaching, review of v1
legacy/           the R/Quarto course and version 1 of the app
```

## Check that everything works

```sh
.venv/bin/python -m pytest -q          # engine, readers, examples, API, export
npm test --prefix frontend             # pipeline layout
npm run build --prefix frontend
```

The Python suite takes a few seconds. It checks, among other things, that both
fixation detectors recover the simulated fixations, that the effects built
into the examples can be found again, that the script shown for each
pymovements step gives the same result as the step, and that an exported
analysis re-runs to identical tables outside the app.

## Limits worth knowing

- Gaze is analysed in pixels of one coordinate system per pipeline (the
  screen, the glasses' scene video, or a snapshot that gaze was mapped onto).
  There is no head-motion compensation and no automatic mapping of glasses
  gaze onto pictures; use Tobii Pro Lab's mapping and its export for that.
- Detection thresholds are in degrees of visual angle, worked out from the
  viewing geometry given in the Load step. For glasses gaze that Tobii mapped
  onto a snapshot, degrees are only approximate.
- What pymovements 0.28 does, the steps do, including three things worth
  knowing: an event's duration runs from its first to its last sample (one
  sample shorter than the time it covers); I-VT does not merge fixations that
  a noise spike split; I-DT counts durations in whole samples and lets each
  fixation reach one sample into the following saccade. Each is explained on
  the step. Pupil size cannot be smoothed, because pymovements smooths gaze only.
- The Tobii readers follow the documented file formats and were tested on the
  simulated files in this repository, not yet on a real Glasses 2 recording.
  With your first real file, compare *File as read* with the original and read
  the remarks of the Load step.
- No statistics are computed. The app prepares the tables; JASP, jamovi or R
  do the testing.
- No user accounts. An upload is reachable by anyone who has its pipeline;
  put the server behind a password if recordings are sensitive.
